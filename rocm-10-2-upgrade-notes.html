ROCm 10.2 Upgrade Notes: vLLM 0.32 Images, a Breaking amd-smi CLI, and a CRIU Restore Gap on MI350X

19 November 2026 · Anpoo Sivanadi

AMD shipped ROCm 10.2.0 on November 18, 2026, the latest drop on its six-week cadence. The launch blog calls it a release that "prioritizes stability," and most of the headline list reads that way: newer framework builds, more RCCL tuning, a smaller library footprint, a unified profiler command. AMD also says 10.3 will land "slightly later" than usual because of the holidays, so 10.2 is probably what most AMD clusters will run into January.

That makes it worth reading the release notes rather than the blog. A stability release can still change the things your automation depends on, and this one does. Below is what I would look at before rolling it across Instinct nodes. Figures come from AMD's release notes and blog. Anything that is my own reading or arithmetic is labeled that way.

1. Framework versions moved, and the serving builds still trail upstream

The validated framework set changes like this:

Component ROCm 10.1 support ROCm 10.2 support
PyTorch 2.12.0 2.15.0
JAX 0.11.0 0.11.2
vLLM 0.29.0 0.32.0
SGLang not listed 0.5.21

vLLM ships as prebuilt Docker images and Python wheels, SGLang as Docker images, and both now run on Python 3.14. The official vLLM images bundle AITER (AMD's AI Tensor Engine for ROCm). MI300X, MI325X, MI350X and MI355X get prebuilt AITER kernels. On Radeon and Ryzen AI, the kernels compile the first time they are used.

My reading: vLLM v0.34.0 came out on November 16, two days before this release. AMD's validated image is two minor versions behind. That is normal for a vendor-validated stack, but the gap matters this time. 0.34 changed the KV cache sizing default, removed Model Runner V1 and dropped -rocm72 image tags, which I covered in my 0.34 notes. If you run AMD's image, you are on 0.32 behavior. If you run upstream 0.34 on 10.2, that pairing is not on AMD's validated list. Pick one on purpose.

2. PyTorch from TheRock no longer bundles ROCm

One line in the blog is easy to miss: "PyTorch packages built by TheRock now install ROCm as a separate dependency, instead of bundling it inside the PyTorch package itself."

My reading: this is good for image size and for keeping one ROCm per container. It also means a lockfile or a Dockerfile that assumed pip install torch brought its own ROCm runtime can now resolve a different ROCm than the one on the base image. I would pin the ROCm dependency explicitly and check torch.version.hip in a startup probe.

3. Two CLI changes that break scripts

These are the changes I would treat as breaking, and the release notes label them that way.

amd-smi exit codes and output. The amd-smi CLI now returns more specific exit codes that match the code field in the error message. amd-smi ras now exits non-zero when a CPER file fails to decode, where it used to exit 0. set and reset keep going past a per-device failure instead of stopping. Errors in --json and --csv output gain an error_type field, and --csv rows gain a third column. Any health check, node-problem detector or exporter that parses two-column CSV or treats any non-zero exit as "GPU bad" needs a look.

rocprof-compute flags. In profile mode, -d used to select dispatches. It now sets the output directory, and dispatch selection moves to --kernel-iteration-range. Dispatch IDs now start at 1. A CI profiling job that passes -d 5 will quietly write to a directory called 5 instead of filtering. The analyze mode --gui and --tui options are deprecated.

4. Three known issues worth knowing before you schedule the rollout

MI300A spontaneous reboots on RHEL 10.3. On kernels that enable the X86_FEATURE_INVLPGB broadcast TLB flush, including RHEL 10.3, the TLBSYNC instruction can hang on MI300A. That trips a CPU machine-check watchdog that sync-floods the data fabric. The workaround is clearcpuid=419 on the kernel command line (TheRock #10102). RHEL 10.3 is also new in this release's support list, so a team upgrading the OS and ROCm together could walk straight into this.

CRIU restore fails on MI350X. criu dump works, but criu restore fails for any workload that creates a GPU queue. The AMDKFD_IOC_CRIU_OP ioctl returns Invalid argument, and AMD lists no workaround (TheRock #10103). My reading: if you were planning GPU checkpoint and restore for cold starts or preemption on MI350X, it does not work on this release. You get checkpoints you cannot restore, which is worse than getting none.

In-place amdgpu-dkms upgrade. Upgrading amdgpu-dkms without a reboot can leave the old amdttm and amdkcl modules resident. Loading the new driver then fails with could not insert 'amdgpu': Invalid argument. The workaround is to run modprobe -r amdgpu amdttm and confirm with lsmod that nothing from amdgpu|amdxcp|amddrm|amdttm|amd_sched|amdkcl is still loaded before reinstalling. For node pools that drain and reboot on driver changes, this is a non-issue. For anyone doing live driver swaps, it is a failed node.

For the MI355X, the firmware and driver matrix lists PLDM bundle 01.26.01.06 or later (01.26.00.02 also listed) and amdgpu driver versions from 30.30.0 through 31.70.0. Your OEM ships the firmware, not AMD, so check that matrix against what is actually flashed.

5. Changes that help operators

  • hipBLASLt catalogs are compressed. Debian and RPM packages now install solution catalogs as zlib-compressed .dat.zlib files, which shrinks them from about 3.8 GB to about 194 MB. By my arithmetic that is roughly a 95% cut, which matters for image pull time on large node pools. The cost is decompression on first use, so the first GEMM after a cold start pays extra. hipSPARSELt does the same and cites more than 90% savings. If you measure TTFT on a freshly started pod, expect that first-call overhead to show up.
  • amdsmi on PyPI. pip install amdsmi (version 27.2.0) bundles the library, so the Python API works without a ROCm install. It needs pip 20.3 or later. Older pip installs an unrelated legacy 7.0.2 package. That is a nice trap for a slim exporter image.
  • Fabric faults alongside GPU errors. amd-smi ras --cper now reports fabric link events in the same CPER output as GPU errors. amdsmi_get_fabric_cper_entries() exposes them through the API. amdsmi_get_link_topology() queries the link between two GPUs on bare metal in one call.
  • Power profiles. amd-smi static --ampp and the matching C API expose the driver's predefined power and performance profiles, enumerated at runtime.
  • Profiling. The Streaming Performance Monitor gains a device-wide counting mode that samples between kernel dispatches, on gfx1200, gfx1201 and gfx1250. rocsys is an experimental single entry point for the Systems Profiler. rocprof-sys-attach can now attach from the host to a process inside a container. Infinity Storage I/O counters show up in the profiler (ROCPROFSYS_USE_HIPFILE) and in AMD-SMI. Experimental memory bandwidth analysis on MI350 Series flags L1, L2 or fabric bottlenecks with --experimental --membw-analysis.
  • hipFile on LVM and mdraid. GPU-direct storage reads now work through logical volumes and software RAID. PyTorch gets load_storage and save_storage APIs on top of hipFile, and fio 3.43 supports it, so you can benchmark it before you trust it.
  • rocFFT 64-bit indexing. Transforms larger than 2^32 elements, or with large strides or batch counts, now switch to 64-bit offsets automatically instead of overflowing.

6. The smaller items

RCCL gets more tuning for single-node, eight-GPU Radeon PCIe servers, validated with four-way tensor-parallel vLLM. That is relevant if you run R9700-class boxes for inference and irrelevant on Infinity Fabric Instinct nodes. hipBLASLt adds complex GEMM (CGEMM, ZGEMM) on gfx942 and gfx950, with rocBLAS routing those calls to it. SR-IOV support adds the MI350P with GIM 9.4.0.K on Ubuntu 24.04. OS support adds RHEL 10.3, RHEL 9.9 and SLES 16.1. The 18 newly supported Ryzen laptop parts (gfx1103) and the Radeon PRO W7900D matter for local development, not clusters.

There is also an upcoming change in the compiler. LLVM runtime libraries move from lib/llvm/lib to lib/llvm/lib/x86_64-unknown-linux-gnu. For now, symlinks keep the old paths and -target x86_64-pc-linux-gnu working. If your build scripts hardcode those paths, fix them while the symlinks are still there.

My rollout checklist

  1. Grep health checks and exporters for amd-smi CSV parsing and exit-code handling. Run them against a 10.2 node before the fleet.
  2. Grep CI profiling jobs for rocprof-compute ... -d.
  3. Decide whether you run AMD's vLLM 0.32 image or upstream 0.34, and test that exact pairing.
  4. Pin the ROCm dependency for TheRock PyTorch wheels.
  5. On MI300A with RHEL 10.3, add clearcpuid=419 before the first boot.
  6. Do not plan on CRIU restore on MI350X with this release.
  7. Reboot on driver upgrades, or script the full module unload.
  8. Measure first-request latency on a cold pod to see what the compressed catalogs cost you.
